# Spec Delta

## Purpose

Defines the documentation surface for the examples: the "Examples" gallery section of the
main book, the separate "Machine Learning with Sciencekit" book, and the cross-references
and code-tab rendering that connect them.

## ADDED Requirements

### Requirement: Main book exposes an Examples section

The main book SHALL contain an "Examples" section whose taxonomy mirrors the
scikit-learn gallery's organization by algorithm family, with one page per ported
example.

#### Scenario: Family pages exist for the ported families

- **WHEN** the main book's summary is read
- **THEN** the Examples section lists one family page per family that has ported
  examples

#### Scenario: Gallery mirrors the scikit-learn organization

- **WHEN** a family page is compared with the corresponding scikit-learn gallery section
- **THEN** the examples are grouped by algorithm family in the same way

### Requirement: Gallery pages are generated from the example's sources

A gallery page SHALL NOT contain hand-written copies of the example's code; its code
blocks SHALL be generated by inlining the example's own source files, and its prose
SHALL be generated from the catalog record and from the assertions of the example's
companion test.

#### Scenario: The shown code is the running code

- **WHEN** a gallery page is built
- **THEN** its code blocks are inlined from the example's source files and match them
  byte for byte

#### Scenario: Prose comes from the record

- **WHEN** a gallery page is built
- **THEN** its dataset origin, knob spectrum and expected output are taken from the
  catalog record and the companion test, not from hand-written text

#### Scenario: A missing language file yields no tab

- **WHEN** the file of a language does not exist for an example
- **THEN** that language contributes no tab, and no empty tab is rendered

### Requirement: Example pages credit the scikit-learn example they adapt

An example page SHALL carry a credit line naming the scikit-learn example it adapts and
the source file it was ported from.

#### Scenario: Credit line is present

- **WHEN** a gallery page is read
- **THEN** it names the scikit-learn example it adapts and its source path

### Requirement: Example pages state intent, data, configuration and output

An example page SHALL state what the example demonstrates, which dataset it uses and
where that dataset comes from, which estimators and configuration settings it exercises,
and what output the reader must expect.

#### Scenario: Page documents the dataset origin

- **WHEN** an example page is read
- **THEN** it names the dataset and its source, including whether the dataset is synthetic

#### Scenario: Page documents the configuration spectrum

- **WHEN** an example page is read
- **THEN** it lists the configuration settings compared and the effect each one is
  expected to produce

### Requirement: Example pages are grounded in the real code

An example page SHALL reference the runnable example target of its example and the companion test
module that exercises it, and its narrative SHALL match the behavior asserted by that
test. The quoted numbers SHALL be rounded to a documented precision and the companion
test SHALL assert them within a documented tolerance, so that the page is stable across
platforms and math backends.

#### Scenario: Page links to the runnable example

- **WHEN** an example page is read
- **THEN** it states the command that runs the example target

#### Scenario: Page reflects the asserted behavior

- **WHEN** the companion test of an example is read
- **THEN** the metrics quoted on the page are the ones the test asserts

#### Scenario: Numbers are stable across platforms

- **WHEN** the example runs on two different platforms or math backends
- **THEN** the quoted numbers agree within the documented tolerance

### Requirement: Stale pages are detected in continuous integration

The pages of both books SHALL be generated from the corpus, and the documentation build
SHALL verify that the committed pages match a fresh generation, so that a page showing
code that no longer exists fails the build.

#### Scenario: A changed example invalidates its page

- **WHEN** an example's source changes and its page is not regenerated
- **THEN** the documentation build fails and names the stale page

#### Scenario: A reproducible generation passes

- **WHEN** the pages are regenerated from an unchanged corpus
- **THEN** the result is identical to the committed pages and the build passes

### Requirement: The Machine Learning book is a separate book

The "Machine Learning with Sciencekit" content SHALL live in a book separate from the
main documentation book, and the main book SHALL reference it from a section of its
summary.

#### Scenario: Separate book exists

- **WHEN** the documentation tree is inspected
- **THEN** the machine-learning book has its own configuration, summary and chapters,
  separate from the main book's

#### Scenario: Main book references it

- **WHEN** the main book's summary is read
- **THEN** a section links to the separate book

### Requirement: Machine Learning chapters teach cause and effect

A chapter of the Machine Learning book SHALL introduce its concept from first principles,
SHALL present a spectrum of configurations of the algorithm it teaches, and SHALL explain
the cause-and-effect relationship between each configuration and the observed behavior,
grounded in the real example code and the real companion tests.

#### Scenario: Configuration spectrum is presented

- **WHEN** a chapter about an algorithm is read
- **THEN** it shows at least two configurations of that algorithm and the behavior each
  produces

#### Scenario: Chapter is grounded in real code

- **WHEN** a chapter is read
- **THEN** it references the example code and the companion tests that demonstrate the
  behavior it describes

### Requirement: Cross-references connect the gallery and the book

Every example page SHALL link to the chapter that teaches its concept, and every chapter
SHALL link to the examples that demonstrate it.

#### Scenario: Bidirectional links

- **WHEN** an example page and the chapter it references are read
- **THEN** each one links to the other

### Requirement: Code blocks are rendered as language tabs

Where a page shows the same example in several languages, the code blocks SHALL render as
tabs of one grouped widget, one tab per language, and a language whose binding is not yet
implemented SHALL be marked as not yet available rather than silently omitted.

#### Scenario: Tabs switch the shown language

- **WHEN** a reader selects a language tab
- **THEN** the corresponding code block becomes visible and the others are hidden

#### Scenario: Unavailable language is marked

- **WHEN** a language's binding is not implemented
- **THEN** its tab is present and states that the binding is not available yet

### Requirement: Documentation diagrams are Mermaid

Every diagram added to the Examples section and to the Machine Learning book SHALL be a
Mermaid diagram rendered by the book theme, and ASCII-art diagrams SHALL NOT be used.

#### Scenario: Diagrams render

- **WHEN** a page containing a Mermaid diagram is built
- **THEN** the diagram renders as an SVG figure without errors
